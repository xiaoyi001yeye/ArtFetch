## 1. 背景与定位

ArtFetch 的 `/m` 是管理员和审核人的移动端入口，`/expert` 继续作为专家提交本人评估的独立入口。

手机端评估项目从原来的“列表 + 新建”扩展为日常完整管理入口，覆盖项目详情、编辑、发布、提交审核、审核和删除。桌面端仍保留复杂指标配置与大批量作品处理能力。

## 2. 功能范围

### 2.1 本期包含

1. 评估项目列表和分页。
2. 五步新建评估项目。
3. 项目详情，按概览、作品、专家、指标、审核记录分页签展示。
4. 未发布项目编辑，复用新建表单并按页签编辑。
5. 每个编辑页签独立保存。
6. 发布前完整性检查、二次确认和项目发布。
7. 查看项目进度和每件作品的专家评估结果。
8. 全部专家评估完成后提交审核。
9. 指定审核人或管理员执行项目审核。
10. 整个项目审核通过。
11. 驳回某位专家对某件作品的单条评估，驳回原因必填。
12. 查看审核历史。
13. 删除草稿或待发布项目。
14. 所有敏感操作使用后端权限校验并写入审计日志。

### 2.2 暂不包含

1. 撤回已发布项目。
2. 修改已发布或已经开始评估的项目配置。
3. 删除已发布项目。
4. 整项目笼统驳回；驳回必须精确到专家评估记录。
5. 在手机端逐项细调指标的分值范围、输入控件和评分说明。
6. 超过预览上限的批量全量选择。
7. OR 条件、条件分组或高级查询语法。

## 3. 用户与权限

手机端沿用现有稳定权限码，不新增移动端专属权限：

| 功能 | 权限码 |
|---|---|
| 查看列表和详情 | `evaluation:view` |
| 新建 | `evaluation:create` |
| 编辑 | `evaluation:update` |
| 发布 | `evaluation:publish` |
| 删除 | `evaluation:delete` |
| 提交审核 | `evaluation:submit-review` |
| 查看评估结果 | `evaluation:result:view` |
| 进入审核 | `evaluation-audit:view` |
| 审核通过 | `evaluation-audit:approve` |
| 驳回单条评估 | `evaluation-audit:reject-review` |
| 查看审核历史 | `evaluation-audit:history:view` |

审核数据范围：

- 指定审核人可以审核分配给自己的项目。
- 管理员拥有兜底审核能力。
- 其他用户即使能查看项目，也不能执行通过或驳回。
- 前端隐藏按钮只用于改善体验，后端控制器和服务层必须同时校验权限及数据范围。

## 4. 路由与信息架构

| 路由 | 页面 |
|---|---|
| `/m/evaluations` | 项目列表 |
| `/m/evaluations/new` | 新建项目 |
| `/m/evaluations/:id` | 项目详情 |
| `/m/evaluations/:id/edit` | 分页签编辑 |
| `/m/evaluations/:id/audit` | 项目审核 |

项目详情页签：

- 概览：状态、审核人、进度、说明、筛选条件和审核结果。
- 作品：作品状态和各专家评估结果入口。
- 专家：每位专家的完成进度和驳回数。
- 指标：项目指标摘要。
- 审核记录：审核动作、审核人、目标专家、原因和时间。

## 5. 状态与操作边界

| 项目状态 | 手机端允许操作 |
|---|---|
| `DRAFT` / `PENDING` | 查看、编辑、发布、删除 |
| `PUBLISHED` | 查看项目和专家进度 |
| `IN_PROGRESS` | 查看进度和已提交结果 |
| `READY_FOR_REVIEW` | 查看、提交审核 |
| `IN_REVIEW` | 查看、审核通过、驳回单条评估 |
| `REVIEW_REJECTED` | 查看整改进度、重新提交审核 |
| `COMPLETED` | 查看最终结果和审核历史 |
| `CANCELLED` | 不在正常列表中展示 |

## 6. 新建与编辑

### 6.1 新建

继续使用五步流程：

1. 基本信息。
2. 筛选作品。
3. 确认作品。
4. 专家与指标。
5. 确认创建。

作品预览最多返回前 100 件，默认全选当前预览结果。至少需要一件作品、一位专家和一个指标。

### 6.2 编辑

编辑复用新建表单和数据加载逻辑，改为以下可直接切换的页签：

1. 基本信息。
2. 筛选作品。
3. 确认作品。
4. 专家。
5. 指标。

每个页签提供“保存本页”。关联数据保存时必须携带当前完整的作品、专家和指标，防止覆盖其他页签配置。只有 `DRAFT` 或 `PENDING` 项目可以编辑。

## 7. 发布

- 发布前显示作品数、专家数和指标数，并要求二次确认。
- 后端必须确认作品、专家、评估记录和指标均已配置。
- 发布成功后状态变为 `PUBLISHED`，配置锁定，专家端可以看到项目。
- 第一版不提供撤回发布。
- 发布动作记录审计日志。

## 8. 提交审核与审核

### 8.1 提交审核

- 只有 `READY_FOR_REVIEW` 或 `REVIEW_REJECTED` 项目可以提交。
- 所有专家评估必须已经提交或重新提交。
- 提交后项目进入 `IN_REVIEW`。

### 8.2 审核

- 审核页逐件展示所有专家的指标结果、最终估价和整体评语。
- 审核通过作用于整个项目，项目进入 `COMPLETED`。
- 驳回作用于单条“专家 + 作品”评估记录，原因必填。
- 驳回后项目进入 `REVIEW_REJECTED`，对应专家只修改被驳回记录。
- 审核通过与驳回均记录业务审核历史和系统审计日志。

## 9. 删除

- 只允许删除 `DRAFT` 或 `PENDING` 项目。
- 删除前必须二次确认。
- 后端继续使用软删除并将项目标记为 `CANCELLED`。
- 删除操作记录审计日志。

## 10. 验收标准

1. 有权限用户可从手机端项目列表进入详情。
2. 列表和详情只显示当前状态允许且当前用户有权限的操作。
3. 未发布项目可按页签编辑并独立保存。
4. 发布前执行完整配置校验，发布后不能继续编辑或删除。
5. 全部评估完成后可提交审核。
6. 指定审核人和管理员可在手机端审核。
7. 审核通过按项目执行；驳回精确到单条专家评估且原因必填。
8. 被驳回记录重新提交后，项目可再次提交审核。
9. 项目详情可以查看作品、专家、指标、进度、评估结果和审核历史。
10. 所有接口均有后端权限与数据范围校验，敏感动作均有审计记录。
