# Admin 手机端创建评估项目 PRD

## 文档信息

| 项 | 内容 |
|---|---|
| 当前版本 | v1 |
| 文档状态 | 已确认范围 |
| 最后更新日期 | 2026-06-19 |

## 1. 背景

当前 ArtFetch 已支持管理员在桌面后台创建评估项目，但手机端尚无评估项目创建入口。

现有移动端分为两类：

- `/m`：偏管理员的数据移动端，已有艺术品、训练集、我的账号等能力。
- `/expert`：专家评审移动端，仅用于专家查看分配项目和提交评审。

创建评估项目属于管理员管理动作，应加入 `/m` 移动端，而不是加入 `/expert` 专家端。

## 2. 目标

- 允许 admin 在手机端快速创建评估项目。
- 复用现有后端创建接口和权限体系，不为第一版新增专用后端接口。
- 在手机端提供轻量、分步的完整创建流程。
- 保持桌面端仍是复杂配置和后续精细编辑的主要入口。

## 3. 用户与权限

### 3.1 目标用户

第一版仅面向 admin 手机端。

### 3.2 权限要求

第一版复用现有 API 和权限：

- `evaluation:view`：查看评估项目列表。
- `evaluation:create`：创建评估项目。
- `user:view`：加载审核人和专家候选用户。
- `evaluation-template:view`：加载指标模板和模板指标项。

admin 默认拥有全部权限，因此第一版不新增面向非 admin 的受限查询接口。

如果后续要开放给“项目管理员”等非 admin 角色，应单独设计创建选项接口，例如 `/api/evaluations/create-options`，以避免要求业务角色拥有完整用户管理权限。

## 4. 功能范围

### 4.1 本期包含

1. 在 `/m` 管理员移动端新增评估项目入口。
2. 新增移动端评估项目列表页 `/m/evaluations`。
3. 新增移动端创建评估项目页 `/m/evaluations/new`。
4. 创建流程采用分步向导。
5. 支持配置项目名称、说明、审核人。
6. 支持配置艺术品筛选条件。
7. 支持预览匹配艺术品。
8. 支持确认本次纳入评估的艺术品。
9. 支持手动多选专家。
10. 支持选择一个指标模板并导入模板指标。
11. 提交前展示创建摘要。
12. 调用现有 `POST /api/evaluations` 创建评估项目。

### 4.2 暂不包含

1. 不加入 `/expert` 专家移动端。
2. 不做仅填写名称的空草稿创建。
3. 不新增后端创建接口。
4. 不新增专家组或专家模板。
5. 不在手机端细调指标必填、分值范围、评分说明等配置。
6. 不在手机端支持超过预览上限的批量全量选择。
7. 不新增高级筛选条件组、OR 条件或复杂查询语法。
8. 不要求手机端完整替代桌面评估项目编辑器。

## 5. 信息架构

### 5.1 底部导航

当当前用户拥有 `evaluation:view` 时，`/m` 底部导航新增“评估”入口。

建议导航项：

- 艺术品
- 评估
- 训练集
- 我的

如果用户没有 `auto-evaluation:dataset:view`，训练集入口仍按现有逻辑隐藏。

### 5.2 路由

- `/m/evaluations`：移动端评估项目列表。
- `/m/evaluations/new`：移动端新建评估项目。
- 后续可扩展 `/m/evaluations/:id`：移动端轻量详情。

## 6. 移动端评估项目列表

第一版列表用于承接新建入口和创建后的结果确认。

列表应展示：

- 项目名称。
- 项目状态。
- 艺术品数量。
- 专家数量。
- 审核人。
- 更新时间或创建时间。

列表操作：

- 刷新。
- 新建评估项目。

第一版不要求提供发布、删除、编辑、审核等复杂操作。

## 7. 创建流程

手机端创建采用分步向导，而不是一个超长表单。

### 7.1 步骤一：基本信息

字段：

- 项目名称，必填。
- 项目说明，选填。
- 审核人，必填。

审核人候选：

- 用户角色包含 `AUDITOR` 或 `ADMIN`。

默认值：

- 如果当前登录用户在审核人候选列表中，默认选择当前用户。
- 否则不默认，要求用户手动选择。

### 7.2 步骤二：筛选作品

第一版支持完整桌面端筛选字段：

- 标题。
- 拍品编号。
- 作者。
- 材质。
- 估价。
- 拍卖公司。
- 拍卖会。
- 拍卖专场。
- 拍卖日期。
- 抓取任务。
- 外部 ID。
- 是否有高清大图。

默认条件：

- `作者` `包含`。

操作符规则：

- 普通字段支持 `包含`、`等于`、`年份`、`不为空`。
- `是否有高清大图` 只支持 `等于`，值为 `是` 或 `否`。
- 选择 `不为空` 时隐藏值输入。

不支持：

- OR 条件。
- 条件分组。
- 高级查询语法。

### 7.3 步骤三：确认作品

用户点击预览后，调用现有接口：

- `POST /api/evaluations/preview-artworks`

预览规则：

- 第一版沿用现有上限，最多预览前 100 件。
- 预览后默认全选当前返回的作品。
- 允许用户逐件取消选择。
- 提供“全选”和“清空选择”。
- 显示 `已选择 X / 当前预览 Y 件`。

校验：

- 至少选择 1 件艺术品才能进入后续步骤或提交。

提示：

- 当预览结果达到 100 件时，应提示可能还有更多匹配作品，建议收窄筛选条件或到桌面端处理大批量项目。

### 7.4 步骤四：专家与指标

专家选择：

- 复用 `GET /api/users` 获取用户列表。
- 候选专家为角色包含 `EXPERT` 的用户。
- 支持搜索姓名或用户名。
- 手动多选专家。
- 至少选择 1 位专家。
- 不默认选择所有专家。
- 第一版不做专家组。

指标选择：

- 必须选择 1 个指标模板。
- 复用 `GET /api/evaluation-metric-templates` 加载模板。
- 复用 `GET /api/evaluation-metric-templates/{id}/items` 导入模板指标项。
- 展示模板包含的指标数量和指标名称。
- 第一版不支持从指标库逐个选择指标。
- 第一版不支持在手机端编辑指标必填、分值范围、评分说明等细节。

如果没有可用指标模板：

- 手机端不允许继续创建。
- 提示用户先到桌面端配置指标模板。

### 7.5 步骤五：确认创建

提交前展示摘要：

- 项目名称。
- 审核人。
- 筛选条件数量。
- 将纳入的艺术品数量。
- 已选择专家数量。
- 已选择指标模板。
- 模板指标数量。

提交规则：

- 所有必填项通过校验后，调用现有 `POST /api/evaluations`。
- 创建成功后跳转到 `/m/evaluations` 或移动端轻量详情页。
- 成功提示“评估项目已创建”。

## 8. 状态与后续编辑

现有后端创建后项目状态为 `PENDING`。

手机端第一版只负责创建，不负责完整后续管理。

创建后如需：

- 精细调整指标。
- 大批量处理作品。
- 发布项目。
- 删除项目。
- 审核项目。

应继续使用桌面后台。

## 9. 后端与数据约束

第一版复用现有接口。

创建接口：

- `POST /api/evaluations`
- 权限：`evaluation:create`

请求必须包含：

- `name`
- `description`
- `auditorId`
- `criteria`
- `artworkIds`
- `expertIds`
- `metrics`

其中：

- `artworkIds` 不能为空。
- `expertIds` 不能为空。
- `metrics` 不能为空。

因此第一版不支持只创建空项目草稿。

## 10. 验收标准

1. admin 登录 `/m` 后，能看到“评估”入口。
2. admin 能进入 `/m/evaluations` 查看评估项目列表。
3. admin 能从移动端列表进入新建评估项目流程。
4. 新建流程按基本信息、筛选作品、确认作品、专家与指标、确认创建分步完成。
5. 审核人默认选择当前 admin 自己，前提是当前 admin 在审核人候选列表中。
6. 筛选条件支持桌面端已有字段，不新增高级筛选逻辑。
7. 预览作品最多使用前 100 件，预览后默认全选。
8. 用户可以取消选择作品，作品数量为 0 时不能提交。
9. 用户必须至少选择 1 位专家。
10. 用户必须选择 1 个指标模板。
11. 手机端不允许细调模板导入后的指标配置。
12. 创建成功后后端生成 `PENDING` 状态评估项目。
13. 创建成功后可以在移动端评估列表中看到该项目。
14. 非 admin 或缺少对应权限的用户不能访问相关路由。

## 11. 后续可选增强

- 为非 admin 项目管理员新增受限创建选项接口。
- 增加移动端评估项目轻量详情页。
- 增加移动端发布项目能力。
- 支持专家组或专家模板。
- 支持按筛选条件创建并锁定全部匹配结果。
- 支持大批量作品分页选择。
- 支持移动端微调指标配置。
